# 统计口径与打卡交互调整

日期：2026-10-25，业务时区 Asia/Shanghai。

本次根据用户确认，统一计划完成率、自然日打卡和取消计划的数据范围；简化为一键打卡，将学习历史改为固定分页，并将焦虑值入口原样移至个人页。本文规则取代之前文档中全局按目标天数汇总、打卡必填内容与时长、历史不断追加的旧交互。

## 统计规则

- 首页学习计划完成率 = 已完成计划数 / 全部未取消计划数。未开始、进行中、已完成、已过期均进入分母；无未取消计划时为 0%。取消数量单列，首页不再计算汇总打卡次数除以汇总目标天数的百分比。
- 单计划详情保留“实际打卡日数 / 该计划目标天数”的坚持目标达成率，最高 100%，不与学习计划完成状态混用。
- 全局累计打卡天数按真实打卡日期去重；同一天两个计划各打一条，全局只算一天。当前、最长连续天数使用同样的数据范围和自然日集合。
- 最近七天每天展示“已打卡 / 未打卡”，对应 1 / 0，不把同一天不同计划的记录数当作天数。
- 用户最终确认：取消计划的全部历史保留、允许查询，但不参与看板所有相关统计。完成率、自然日打卡、连续天数、七天打卡趋势、学习时长、今日与七天进度均排除取消计划。AI反馈使用相同的未取消计划和学习日志范围。
- 取消与删除不同：取消不会删除历史；用户明确删除计划或确认清理周期外打卡时，仍执行已有删除规则。

实现上，后端先得到当前用户的未取消计划 ID 集合，打卡与学习日志都按该集合过滤。此前打卡排除取消计划、学习时长却仍统计的分歧已消除。看板使用同一个只读事务，并一次读取最近七天日志再分类和按日统计；AI反馈的总结按打卡自然日去重，不再把各计划目标天数相加。

## 一键打卡与学习记录

记录页选择计划后可直接点击“今日打卡”，备注可选，不要求填写时长，不调用模型。前端不传时长时，后端按 0 保存，明确表示本操作没有记录学习时长；空备注按空字符串保存，不生成“今天学习了某内容”等虚构描述。

首条有效学习记录仍自动创建当天正式打卡。选择计划、重新进入页面或学习记录保存后，查询当前计划当天真实打卡，存在即显示“今日已打卡”。无法查询状态时允许尝试提交，由后端和数据库唯一约束判断；不同用户、计划和日期的边界校验不变。

单击、自动记录和并发请求最终都受到同一计划行锁与唯一约束保护。一键打卡不会新增 AI 行为日志或推进学习进度。用户可以在当天继续追加学习记录；打卡记录中的关联内容被标为“关联学习片段”，不当成全天总结。纯手动记录标为“打卡备注”，空值展示“未填写备注”，不显示虚构的学习分钟数。

空备注的一键打卡不导入待补分析列表，避免让 AI 分析不存在的学习内容；原有带具体内容的手动记录仍可按需导入。

## 固定分页

学习历史每页 20 条，显示当前页、总页数与总条数，通过上一页、下一页切换。每次成功请求替换本页记录，页面不继续追加。

- 第一页和最后一页禁用越界按钮，请求期间防止重复翻页。
- 请求失败保留原页，重试请求刚才失败的页。
- 删除当前页记录后重新请求当前页；如果删除的是最后一页唯一记录，自动退到新的末页；总记录为零时展示空状态。
- 请求版本号防止过时响应覆盖新结果，后端保留时间与 ID 的稳定倒序分页。
- 历史独立加载，不再从记录页请求看板来读取焦虑值。

## 焦虑值

仅将原有滑块、文案、保存操作和相应样式移到个人页。保留原接口与后端逻辑，不增加情绪历史、模型策略或其他扩展，不让焦虑值参与完成率、进度和打卡规则。

## 可用于课程报告的内容

本次代表性 Prompt 是用户确认：“历史记录全部保留，但是展示板相关的统计数据都不进入计算”，以及一键打卡、固定分页、焦虑值仅迁移页面的要求。AI协助将这些规则映射到服务查询范围、响应字段、页面交互和回归测试；取消与删除、学习进度与出勤指标保持独立。

可学习的方法包括：先明确指标的统计单位与分母；用同一计划集合统一多个统计；状态变化不等于删除历史；只读事务和减少重复查询；结构化打卡与学习日志分工；可选字段的后端默认值；分页总量变化时的边界处理；使用真实HTTP与数据库测试验证状态和统计闭环。
