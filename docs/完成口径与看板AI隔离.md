# 完成口径与看板AI隔离

日期：2026-10-28。本轮实现严格验收第5、6项；第7项仅解释，正式打卡历史和待分析列表的分页未实施。

## 三种口径

| 名称 | 判定 | 对学习计划完成率的影响 |
| --- | --- | --- |
| 人工结束 ENDED（5） | 用户主动停止进行中计划，原进度与历史保留，不能重开 | 不增加完成数，仍在未取消计划分母 |
| 学习成果完成 COMPLETED（1） | 全部学习步骤均达到100%；加权100%但仍有未完成步骤也不能冒充完成 | 增加完成数，与打卡天数独立 |
| 打卡目标达成 | 真实打卡日数达到targetDays | 仅影响打卡目标达成率，不自动完成学习 |

学习完成、人工结束、取消均冻结学习写操作、周期和打卡目标，允许更正名称分类及查询原历史。过期继续沿用既有终态规则。取消退出统计；人工结束不退出历史坚持与时长统计。学习成果基于用户确认与记录，并不等于客观证明掌握知识。

## 旧数据与数据库

新增Flyway V2，不改冻结基线1。V2扩展状态CHECK，将旧版无全部完成步骤却标为COMPLETED的计划改为ENDED并增加version。真正全部步骤完成的历史计划保留COMPLETED，学习与打卡记录不删除。后续结构变更使用V3+。

## AI与首页

删除Java情绪寄语方法、看板响应moodQuote字段及Flask /ai/mood-quote路由。个人焦虑值功能不扩展。统计接口不调用模型；AI周反馈保留，前端独立加载，即使反馈长期未返回也先显示真实统计。页面请求版本保护避免旧反馈覆盖新结果，计划列表失败也不隐藏成功加载的统计。

## 第7项解释

学习日志已有固定分页。正式打卡历史与待分析列表仍一次取全部记录：例如1万条记录会全部传输并渲染，而不是每次只取20条。这是数据量增大后的查询、传输和渲染开销问题，不意味着现有记录丢失。真正分页需要数据库LIMIT/OFFSET或游标、总数、前端翻页和筛选重置配套；本轮未改动它们，也不声称已完成大数据压测。

## 可用于报告的实现点

状态机区分“结束执行”与“达到成果”；后端验证全部步骤而非信任前端或加权数字；历史数据用前向迁移修正；基础业务与外部AI在接口和页面加载上隔离。测试分别验证真实HTTP/MySQL业务、迁移保留历史、终态保护，以及带桩慢反馈和过时响应，不把受控模型或带桩结果写成真实模型质量证明。
