# P1 界面与 AI 降级验收记录

> 历史阶段记录：结果只对应本文当时的规则与代码，不表示当前版本再次通过。当前统计口径、测试层级、可复现命令及机器证据以[测试与验收可信度整改](测试与验收可信度整改.md)和[最新证据索引](verification/README.md)为准。

验收日期：2026-10-12（Asia/Shanghai）

## Mock 与固定数据显示检查

- 删除前端运行时 `mockData.js` 以及契约测试对该文件的依赖。
- 看板和个人页不再用固定文案、固定标签冒充接口结果；无数据、接口失败和 AI 不可用都有独立状态。
- AI 自动拆解失败时不再生成三条通用假步骤，后端返回明确的 503，且不会保存计划。

## 页面状态与布局检查

- 看板、计划列表、计划详情、打卡历史、行为记录和个人页补充了加载、空数据、失败和重新加载状态。
- 计划详情在打卡统计失败时不再展示初始的 0 作为真实统计。
- H5 宽屏增加内容最大宽度和居中底栏，小屏减少横向留白，避免内容过宽或窄屏拥挤。
- 前端 `npm run verify` 已通过 API 契约、核心页面状态检查和 H5 构建。

## AI 服务关闭验收

保持 Python AI 服务关闭，只启动 MySQL 与 Java 后端：

- AI 拆解返回 `code 503`，消息提示切换手动创建。
- 前端收到 AI 创建失败后自动切换到手动创建模式，并保留用户已填写的计划字段。
- 手动创建计划不调用 `AIService`，对应自动化测试通过。
- 实际 HTTP 闭环仍成功完成手动创建、编辑、三次打卡、历史查询和统计更新。
- 实测统计为：3 个打卡日、当前连续 3 天、最长连续 3 天、目标 5 天完成率 60%、看板打卡增量 3。
- 验收生成的计划及关联打卡已通过删除接口清理。

后端对 AI 请求设置 2 秒连接超时和 5 秒读取超时，避免 AI 故障长时间阻塞用户界面。
