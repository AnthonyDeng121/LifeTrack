# 首页表单与学科拆解优化

> 历史阶段记录：结果只对应本文当时的规则与代码，不表示当前版本再次通过。当前统计口径、测试层级、可复现命令及机器证据以[测试与验收可信度整改](测试与验收可信度整改.md)和[最新证据索引](verification/README.md)为准。

## 本次任务目标

根据联调反馈修复首页问候语、冗余文字、筛选含义、手动任务表单布局和 AI 学科拆解泛化问题，并说明目标打卡天数的业务意义。修改后继续保留一个记录页面，不重写已创建计划的学习步骤。

## 页面修改前后区别

- 首页原来固定显示“早安”，现在按 Asia/Shanghai 时区显示早上好、中午好、下午好、晚上好或夜深了；进入页面立即刷新，停留时每分钟更新，离开时清理定时器。
- 删除首页板块右侧的“每日打卡次数”“AI 自动归类”和重点任务的“全部”链接；移除详情页同类灰色角标和“可以自行增减子计划……”说明。
- 任务筛选增加“任务类型”“任务状态”标签，第一个选项改为“全部类型”，内部筛选值保持兼容。
- 手动步骤行改为描述、权重和删除按钮的网格布局；权重标签移到输入框外，空值显示短占位词“自动”。桌面与窄屏采用不同列宽，避免文字和边框错位。
- 表单说明改为无边框、无背景和无阴影的普通文字；禁止弹窗内容项被 Flex 压缩，避免长表单把保存按钮压扁。
- H5 日期组件在视口切换时出现关闭态年份选项进入文档流的情况，已限定关闭态不占位，保留打开态的选择交互。
- 首页的子计划数量原先缺少接口字段，导致页面回退显示0；现由后端查询真实子计划数量返回。

## 目标打卡天数对应的课程要求

原始 `综合实践项目选题与验收标准.docx` 的选题9“学习计划与打卡系统”要求计划周期设置、每日打卡及真实完成率/周期统计，没有强制要求字段必须叫“目标打卡天数”。`targetDays` 是本项目实现“在计划周期内希望坚持多少天”这一目标的方式，属于主学习计划，不是某个子计划或课程题目编号。

例如周期30天、目标打卡20天，实际有效打卡5天，则打卡目标完成率为25%。同一天多次学习记录仍只计一个打卡日。知识学习进度由子计划权重和实际进度计算，达到出勤目标不会把所有学习步骤自动改成完成。

用户在创建表单中看到字段用途，在首页看到“打卡目标完成率”，在详情中看到“已打卡 X / 目标 Y 天”和“还差几天/已达成”。计划结束、取消或学习已完成但出勤未达标时，分别显示对应反馈；没有新增消息推送或定时提醒服务。

## AI 拆解修复方法

原 Prompt 主要限制步骤数、15字描述和权重，对学科知识内容约束不足。新 Prompt 要求识别领域核心概念和学习依赖，每步包含具体知识点、动作和可验证产出，允许保留协议、注解、工具等必要信息；用计算机网络和 Spring Boot 的具体程度作为对照示例，并要求其他目标按自身领域重新组织。

程序会检测空步骤、重复步骤、非法权重及“阅读基础教材”“完成在线课程”等纯通用模板。明显不合格时最多要求模型纠正一次，仍失败则明确返回失败，不生成固定学习清单兜底。

真实联调中发现模型还会算错权重之和。此部分改为确定性计算：保留模型建议的相对重要性，以四位小数归一化并分配剩余单位，确保每项为正且合计为1；不因模型加法错误丢弃有效的学习内容。

## 验证记录

- 前端检查上海业务时区及凌晨、早上、中午、下午、晚上的时段边界和跨日日期。
- 检查真实统计驱动的未达标、已达标和周期结束反馈；两次不同日期的打卡能使2天目标从50%变为100%，学习进度仍保持原值。
- Python 测试包含具体内容原样返回、通用模板纠正、纠正失败不伪造数据、非法 JSON、非法权重与重复步骤、相对权重归一化。
- 真实模型生成的计算机网络计划包含OSI/TCP-IP分层、以太网、IP子网划分、TCP/UDP、路由协议、DNS、Wireshark等；Spring Boot计划包含Maven启动、自动配置、REST接口、JPA、测试、Actuator、Security等。验证并未要求返回固定措辞或固定答案。
- 使用独立测试账号创建临时计划，检查真实浏览器中问候语、隐藏文字、筛选标签、桌面与390px窄屏表单布局，以及目标完成反馈；临时计划在验证后删除。
- 最终结果：后端52项测试通过，Python6项测试通过，前端API契约、核心页面脚本及H5构建通过。浏览器测得步骤描述、权重输入框均为46px高且顶边对齐；保存按钮桌面44px、窄屏45.75px；说明区边框为0、背景透明且无阴影。

## 可学习与报告内容

本次体现了 AI 与确定性程序的分工：AI 提供领域内容与相对重要性，程序负责数据校验、精确数值、时间和真实统计。界面问题同时使用页面脚本测试、浏览器几何测量及截图检查，避免只通过构建就判断布局已经正确。

代表性 Prompt：用户指出“学习计算机网络”和“学习Spring Boot”的拆解过于通用，希望突出课程本身。采纳的修改是加强学科约束、放宽过短描述限制、加入模板校验和一次纠正；真实验证后进一步将权重求和从模型任务改为程序计算。
