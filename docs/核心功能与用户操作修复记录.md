## 业务语义

正式打卡按用户、计划、日期唯一。手动打卡使用结构化日期、内容和整数分钟，不增加子步骤学习进度，也不生成 AI 行为日志。提交成功后保留表单，便于查看和重复验收；再次提交由后端拒绝，不重复累计时长。失败时保留输入，用户可进入相应计划查看打卡历史。

AI 学习记录可以同日多次追加，一次输入可能保存多个步骤日志；首次有效记录会自动生成正式打卡，已经存在当日正式打卡时只追加学习记录。页面把“步骤学习记录条数”与“正式打卡条数”分开显示，不把它们混称为打卡次数。`ActionSyncResponse` 增加：

```text
savedRecordCount：本次实际保存的步骤日志数
newCheckInCount：本次新建的正式打卡数
durationMinutes：本次实际保存日志的分钟合计
```

时长来自后端实际分配并保存的日志，多个步骤或计划不会把同一次输入时长重复相加。新增字段是兼容扩展，前端仍能展示旧响应中的步骤明细。独立手动打卡的时长属于该次正式打卡，AI 追加结果显示本次日志时长，不能将两者都称为同一个累计指标。

原有 AI 故障待补分析保存继续保留，与正式打卡分开。手动打卡可按需导入待分析列表，按钮更名为“导入手动打卡待分析”；不自动调用模型。已完成或已取消计划仍遵守上一轮终态冻结规则。

## 日期与分页实现

计划周期筛选采用区间交集：计划结束不早于查询开始，计划开始不晚于查询结束。支持只填一个边界，也可与状态、分类组合。非法日期范围不请求接口；应用新范围后清除旧批量选择，避免误删旧范围选中的计划。请求序号保证较旧结果不能覆盖新筛选结果。

详情页按计划 ID 和日期查询正式打卡。筛选只影响历史列表，不改变完整计划的完成率、连续天数和最近七天统计，并在页面明确说明。查询失败保留上次成功结果，错误与重试独立显示。

学习历史以每页 20 条分页，默认按 `createdAt DESC, id DESC` 排序，保证同一时间多条记录顺序稳定。加载更多防重复请求、按 ID 去重，失败保留现有列表并重试原页；删除成功后重新查询首页，避免偏移量变化导致遗漏补位记录。刷新请求带本地版本号，过时响应不会覆盖新结果。

情绪状态不再是历史加载的依赖。即使统计请求一直未返回，历史仍能完成加载；统计失败只提示情绪状态问题。详情页也独立处理打卡历史与统计，任一失败不隐藏另一部分可用数据。
