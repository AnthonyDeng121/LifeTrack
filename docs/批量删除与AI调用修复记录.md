# 批量删除与 AI 调用修复记录

验证日期：2026-10-16，业务时区 Asia/Shanghai。

本次增加任务批量选择删除、状态配色与排序，修复 Windows 启停脚本，并排查 AI 创建失败。保留用户已有的 `.gitignore` 修改。

## AI 故障证据和修改

实际配置为智谱接口 `https://open.bigmodel.cn/api/paas/v4/chat/completions`，模型 `glm-4-flash`，密钥从环境变量读取。原后端日志显示调用 `/ai/deconstruct` 约 5 秒后出现 `Read timed out`。原 Python 读取超时为 20 秒，前端为 30 秒，外层先结束等待。

改为模型连接 3 秒、读取 30 秒，后端读取 40 秒，前端 AI 创建读取 50 秒。后端连接 Python 仍为 2 秒。移除未被这条调用链使用的 OpenAI 配置；后端 AI 地址和读取超时可配置。检查 AI 返回码、空步骤和非法权重。前端仅在业务码 503 时降级手动创建，其他错误保留真实提示；401 也会结束请求 Promise。

使用“学会编曲”经后端真实创建两次：分别生成 5、6 个步骤，总耗时约 21.41、19.38 秒。检查成功返回并保存，随后删除临时计划。该结果验证后端、Python、GLM 和持久化完整链路；不保证外部模型永久可用。

新增 `/health` 返回服务、提供商、模型和配置状态，不返回密钥。健康检查不调用付费模型，不表示模型请求必然成功。关闭 Flask debug/reloader，避免后台重复进程。

## 批量删除和状态显示

任务列表增加批量管理、单选、全选当前筛选列表、确认删除与操作中禁用。切换筛选清除选择，返回任务页重新加载真实数据。删除后从后端刷新，移除原来手工拼接不完整任务的兜底代码。

`POST /api/v1/tasks/batch-delete` 接受 `taskIds`，每次 1 至 100 项，正整数、非空并去重；先校验全部任务归属和存在性，再在同一事务内删除任务及子任务、行为日志、打卡记录。

状态在列表和详情中共用颜色：进行中绿色、未开始蓝色、已完成紫色、已取消灰色、已过期橙色。列表依次按进行中、未开始、已完成、已取消、已过期排列，同状态保持接口原顺序。创建弹窗限制桌面最大宽度。

## 启停修复

前端原检测固定访问 IPv4 的 `127.0.0.1`，Vite 在 localhost 的 IPv6 监听可能导致误判。改为 HTTP 检查后端 OpenAPI、前端 localhost 首页和 AI 健康端点，同时检测子进程提前退出并提供日志路径。启动后端前 clean，避免复用损坏的 class；每启动一端立即保存进程记录。启动失败清理进程树，AI 依赖已安装时不再每次执行 pip install。

停止脚本修复 PowerShell 5 JSON 数组的额外嵌套，逐个 PID 停止进程树，并检查失败。已实测完整停止后三个端口释放，再通过一键启动恢复三端并完成 HTTP 就绪检测。
