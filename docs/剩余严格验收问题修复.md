# 2026-10-30 剩余严格验收问题修复

本轮目标：完成原审查第8、9、10、11项，复核此前完成的1—7、12、13项；视频按本人要求不处理。范围是原审查问题，不包含日历热力图、徽章等可选增强。

## 用户问题的直白解释

AI旧记录将步骤推进至20%，后来人工确认完成至100%。再撤销旧AI记录时，应该删除该记录及实际时长、自动出勤影响，保留人工确认的100%；否则“撤销旧事情”会破坏后来独立确认的成果。人工结束计划仍保留原来的学习进度、真实打卡率，不强制100%。步骤全部完成只代表学习100%；打卡也达到目标才COMPLETED。

快照是保存“事情发生当时的数值”：步骤当时权重25%、推进20%，保存计划增量5个百分点。以后步骤权重改成50%，过去这次贡献仍为5个百分点。“取消计划排除”表示取消后的历史仍可查询，但不计看板和反馈；“真实HTTP/MySQL”表示测试真实调用后端并读写数据库，不是给模拟对象填一个期望值。

| 11 当天时长汇总 | 每次读取全计划历史日志再由Java筛一天 | SQL按用户、计划、上海当天[start,nextStart)做COUNT/SUM，只返回两个汇总数；自动备注只取首条，手动备注保留；V6增加匹配索引 |

第11项不意味着不扫描任何历史：计划总学习时长依然由数据库SUM覆盖全部成功日志。优化的是某一天的更新，只查询该日期相关行，并避免传回全量实体。无需引入需要同步维护的累计缓存。

第9项不猜测旧操作来源：历史版本没有保存人工确认的先后证据，不回写虚构的人工确认记录。升级后执行人工确认即可建立新的完成依据；已关闭计划仍禁止撤销。RESET更换学习内容会照旧清零，新的学习日志独立累计。

## 迁移与界面

新增V6，仅扩展待分析状态及日志日期索引，不改V1—V5。DISCARDED不计时、不计打卡、不进待分析分页，删除正文而保留提交标识，避免重发旧请求复活已移除内容。修改不会挪动原发生日期，也不会自动重新调用AI。关闭计划的失败记录可删除，成功历史继续遵守关闭后不可撤销的规则。

页面新增失败记录编辑、整数小时/分钟校验、删除确认、操作期间禁重入、分页回退；保留其他未提交草稿。记录实际能否操作由后端返回并在写入事务内再次检查，不能靠按钮权限兜底。
