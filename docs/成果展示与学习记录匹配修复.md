# 成果展示与学习记录匹配修复

## 任务目标与前后区别

本次处理：提前学完后的评价与展示、最多10个拆解步骤、两个操作按钮字号不一致，以及“整理关系型数据库笔记”导致8个步骤统一增长。

以前首页以打卡目标达成率作为主指标，提前学完也可能一直显示较低百分比；总结只接收行为日志，不能明确区分学习完成与出勤未满。现在首页主指标为已完成学习计划数/全部未取消计划数，坚持目标达成率和累计出勤单列；详情完成后突出“学习目标已完成”，同时保留实际打卡天数、原目标和真实比例。

总结新增当前计划快照：标题、状态、学习进度、原定天数和实际出勤。Prompt明确：提前完成计入学习成果，不要求凑天数；原定坚持目标未满可以客观说明，但不能否定成果。快照不能被描述为“所有计划都在本周完成”。一次输入可能生成多条步骤日志，现在按相同记录时间和原文合并学习事件，合计分摊后的时长，不把子步骤贡献相加为整项计划进度。

真实测试发现模型仍可能省略完成事实，因此增加程序根据持久化数据生成的planOutcomeSummary，首页在AI评价之前展示。该事实摘要固定给出当前已完成/全部计划数、真实打卡次数与原定目标合计，不依赖模型是否遵循Prompt；AI不可用时仍能随降级报告返回。

## 匹配错误的原因与修复

旧后端限制了权限、候选ID、进度上限，却直接接受模型对多个候选步骤的匹配。模型将“数据库”泛化为整门课程后，同一句笔记可以分别给SQL、索引、事务等步骤增加5%。这是匹配范围错误，单纯限制进度增量无法解决。

新Prompt要求区分具体学习动作与学科相关性：整理关系模型概念笔记不能推断做了SQL练习、项目、事务实验或模拟题；否定表述、未来打算及仅出现关键词不能当作学习事实。

新增match_evidence字段。多个步骤需要分别引用用户原文至少4字的独立学习事实；后端在任何写入前验证证据存在、各证据区间不重叠。重复、杜撰、缺失或重叠证据时整次不写入，返回matchingAmbiguous与补充建议，前端保留输入。单步明确匹配仍直接保存；明确描述两项独立学习活动时继续支持推进两个步骤，时长仍只统计一次。

这个校验能阻止同一句话批量套给多个步骤，但原文区间独立不代表语义一定正确，仍依赖模型辨别具体对象，不声称消除所有误判。已有错误历史不会自动删除或重算，避免误改用户数据；可通过记录页撤销对应错误条目后重记。

## 数量和样式

前端提供自动、2至10步；Java请求校验、Python输入范围、上一版步骤长度和输出数量校验同步为10。指定数量仍需满足，模型不符合时纠正一次再失败，不静默截断或凑步骤。上限不影响详情页原有最多100个手动子计划的限制。

“按当前建议重新生成”和“确认方案并保存”现在共用create-btn样式，字号26rpx、高度与行高88rpx。此前前者使用全局按钮字号，后者使用页面字号，造成视觉差异；本次用浏览器computedStyle验证实际字号相同。

## 可学习与报告内容

- 分离成果指标与过程指标，不能为视觉满分而篡改真实出勤数据。
- 为模型输出建立可执行的业务校验，而不是只修改Prompt；范围错误与数值错误应分别处理。
- 数据粒度不同需要分别统计：一次记录、多个步骤日志、一次正式打卡不是同一个数量。
- 回归测试既要拦截一句话推进8项，也要验证明确两项活动仍能正常推进，避免过度限制。

关键Prompt示例：“整理了关系型数据库的笔记最多匹配关系模型概念，不得推断SQL、事务、项目或测验；多个步骤必须引用不同且不重叠的用户原文学习事实。”“COMPLETED表示学习目标已完成，即使出勤未满也不能判为学习未达标。”
