## 目标与修改前后

本次解决六项联调问题：学习与打卡指标含义、自然语言达到100%的边界、保存后弹窗未关闭、固定更新时间、拆解数量与收尾质量、用户反馈调整流程。

以前直接“生成并保存”，用户看到结果时任务已写入数据库，新建框却仍然打开；现在先调用只读预览接口，用户可填写调整建议并重生成，确认方案后才调用创建接口，保存成功立即关闭并清空表单，再刷新列表。生成或保存期间按钮禁止重复提交；重生成失败保留上一版。标题改变使预览失效，建议或数量变化也必须重新生成后再确认，避免保存过时草案。

以前列表没有更新时间字段，前端显示固定兜底“刚刚更新”；现在返回持久化的updatedAt，显示具体年月日时分。字段缺失显示“更新时间未知”，不冒充刚更新。读取不会主动设置更新时间；旧数据周期修复或真实日期状态变化仍可能触发必要更新。

## 两种指标与状态

| 指标 | 计算 | 业务作用 |
| --- | --- | --- |
| 学习进度 | Σ(子计划权重 × 子计划当前进度) | 衡量任务内容完成情况；达到100%自动完成计划 |
| 打卡目标达成率 | min(真实打卡天数 / targetDays, 1) | 衡量学习坚持目标，不替代知识学习进度 |

打卡满了但没学完：打卡达成率100%，学习进度保持真实值，计划继续进行。学完但没打卡满：允许提前完成，实际打卡天数和未达标比例保留；不强迫凑日数、不补造出勤，已完成计划停止新增打卡。详情页分别说明两种情况。每日同一主计划仍最多一条正式打卡记录，多次学习记录单独累积。

界面避免把99.99%四舍五入显示成100%；不足100%的值显示最高99.9%，实际达到100%才显示100%。

## AI完成边界

旧实现只按每次最多30%累加，数学上可以达到100%，但没有完整真实模型闭环验证，也未向模型传当前进度。现在将步骤当前进度一并提供，区分普通投入和明确完成：

1. 普通投入贡献最多30%，子计划最多95%，不能单靠反复泛泛投入堆成完成。达到95%后有效学习仍保存记录、可计当天打卡，实际进度增量为0；撤销和出勤重算仍保留这些有效记录。
2. 用户明确陈述该步骤全部要求的具体产出与验收通过时，模型输出completed=true、completion_evidence原文摘录及正数匹配标志。
3. 后端检查候选步骤归属、有效周期、重复匹配、原文证据至少8字且确实出现在输入中。有效完成按剩余进度计算，而非盲信模型百分比。
4. 实际贡献保存到ActionLog，用于撤销；100%后计划完成，撤销导致进度不足时恢复进行中。
5. 用户仍可在详情页手动确认完成；AI故障仍可保留原始记录、正式打卡并稍后补分析。

模型与原文校验不能证明真实掌握，更不能验证用户自述真实性。原文校验只能阻止模型杜撰证据，并非语义正确性的充分条件。手动确认和撤销仍是必要的用户控制。当前方案不引入考试或外部成果验证。

## 拆解预览与反馈

新增登录保护的`POST /api/v1/tasks/deconstruct/preview`，输入title、guidance、stepCount和previousSteps。后端和Python服务校验输入长度、数量范围；预览服务不调用任何计划持久化方法。前端复用现有创建接口确认保存，无新草案数据库表和额外服务。

8只是生成上限，非固定数量。自动模式由目标范围决定，也可指定2至8步；指定数量必须满足，否则进入一次纠正重试。Prompt要求最后一步包含整体目标的具体综合产出和通过标准，不能只是另一个新知识点。程序检查最后一步有验收相关表述，但这只是最低结构检查，是否真正覆盖目标仍需模型和用户预览共同判断。

## 可用于学习与课程报告

- 区分过程指标（出勤）与结果指标（内容完成），避免混用同一个“完成率”。
- 采用“生成草案—用户反馈—再次生成—确认提交”的交互，消除不满意方案提前落库的问题。
- 模型负责语义建议，程序负责权限、数值边界、证据原文校验、精确计算和持久化约束。
- 保存实际进度增量，使撤销成为可逆操作；用真实模型端到端测试补足Mock测试的盲区。

代表性Prompt要求：“简单目标2~3步，普通课程4~6步，复杂目标7~8步；最后一步写明整体目标的综合产出和通过标准。”“只有用户描述步骤全部要求的产出和验收事实时才标记完成，引用用户原文证据。”用户调整示例：“已有分层基础，重点用Wireshark抓包分析DNS、HTTP和TCP，最后独立分析一次网页访问并验证协议顺序。”

验证命令：后端`mvnw.cmd clean test`；Python`venv/Scripts/python.exe -m unittest -v test_ai_server.py`；前端`npm run verify`；真实模型`node frontend/scripts/verify-ai-live.mjs`。测试结果与浏览器验证在本次提交说明中记录。
