## 配置开关与环境限制

配置开关决定是否启用某个演示入口，环境限制决定当前部署有没有资格使用它。后端采用双重检查，而不是仅靠前端隐藏或接口描述。

| 环境 | 开发登录开关 | 演示手机号开关 | 实际结果 |
| --- | --- | --- | --- |
| 唯一显式环境为 dev | true | true | 两种演示登录可用 |
| 唯一显式环境为 dev | false | true | 仅演示手机号可用 |
| 唯一显式环境为 dev | true | false | 仅开发登录可用 |
| 无显式环境、prod、test、staging | 任意 | 任意 | 两种演示登录均拒绝 |
| dev 与任何其他环境混用 | 任意 | 任意 | 两种演示登录均拒绝 |

变量：`SPRING_PROFILES_ACTIVE`、`AUTH_DEV_LOGIN_ENABLED`、`AUTH_DEMO_PHONE_ENABLED`、`AUTH_DEMO_CODE`。基础配置不默认激活 dev，开关默认关闭；显式 dev 配置默认开启两个演示入口，可分别关闭。根目录一键启动脚本在未指定环境时明确选择 dev，保留课程本地启动体验。

后端 `DevelopmentAuthPolicy` 同时用于登录能力查询和实际服务方法检查。直接调用接口也不能绕过限制。`GET /api/v1/auth/options` 只返回当前可用方式，演示验证码仅在演示手机号入口实际可用时返回。前端先查询能力，再显示相应按钮；查询失败保持关闭并显示重试入口，不猜测环境或写死验证码。

手机号认证目前仍是开发演示，不发送真实短信。非开发环境不提供这两种演示身份认证；本次没有虚构或额外实现生产短信服务。

## 修改前后

| 问题 | 修改前 | 修改后 |
| --- | --- | --- |
| 非法分类 | 创建接口可能返回业务码500 | 创建、编辑、AI创建统一分类解析，返回HTTP400及明确提示 |
| 非法手机号 | 直接substring导致越界并暴露内部错误 | 控制器校验和服务层兜底，手机号必须为有效11位格式，验证码为6位数字 |
| 错误验证码 | RuntimeException归为服务器错误 | 业务参数错误400，禁止认证成功或写入用户 |
| 用户名冲突 | 手机号后四位相同可能生成相同用户名 | 新建演示用户使用随机唯一用户名；已有手机号继续复用原账号 |
| 开发登录 | 仅描述“开发环境”，接口未限制 | 唯一显式dev环境加对应开关，非开发和混合环境均返回403 |
| 微信登录 | 任意code拼接openid即可登录 | 删除路由、服务、DTO、前端封装；访问原路由返回404 |
| 敏感日志 | 输出手机号、验证码及学习记录正文 | 移除正文日志；认证DTO诊断文本排除手机号、验证码、Token；限制框架请求响应调试日志 |
| HTTP状态 | 业务失败通常仍返回HTTP200 | 保留code/message/data，实际HTTP状态同步业务错误码 |
| 内部异常 | RuntimeException原始消息直接返回前端 | 未知异常返回通用500提示，具体异常留在服务端 |
| 看板错误分类 | 不存在、越权统一抛RuntimeException | 分别返回404、403，与其他模块一致 |

微信历史字段保留仅为数据兼容，未删除历史用户或学习数据，也不再用于认证。真实模型回归脚本改用明确dev环境下的隔离演示手机号，不再依赖微信Mock。

## 异常响应与兼容

`ResultStatusAdvice` 在统一响应写出前设置实际错误HTTP状态，不改变正常成功响应结构。参数校验、格式错误、缺失必填参数为400；未登录401；越权或禁用认证403；不存在404；不支持的方法405；重复与数据库约束冲突409；未知服务器异常500。

全局处理器不再直接输出IllegalArgumentException或RuntimeException的原始消息，也修复了非法参数异常消息为空时的二次空指针风险。JSON解析失败日志不记录可能包含认证内容的原始异常文本。

前端原有请求封装已支持非2xx及业务码，无需改变业务页面。PowerShell真实验收脚本增加读取HTTP错误响应JSON的逻辑，继续检查400、409等预期异常，不会把预期业务拒绝误当作脚本网络故障。
