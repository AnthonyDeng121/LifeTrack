# 计划业务规则修复与验收记录

日期：2026-10-25，业务时区 Asia/Shanghai。

本次解决严格验收中发现的五项业务问题：取消计划被子步骤完成、周期修改后越界打卡仍计数、创建产生非法权重、显式状态与日期冲突、完成计划通过新增步骤重新开启。用户明确要求已完成计划不可回退，周期外正式打卡在明确提醒并确认后清零。验证通过后可提交到本地，未经明确要求不推送。

## 修改前后

| 问题 | 修改前 | 修改后 |
| --- | --- | --- |
| 状态绕过 | 完成取消计划的步骤会把计划变成已完成 | 新增、编辑、删除步骤和手动完成统一检查父计划状态；完成步骤仅允许有效周期内的进行中计划 |
| 周期与历史 | 周期缩短后，越界记录仍参与打卡统计 | 保存前查询真实记录、显示影响数量；确认后在同一事务内修改周期并删除周期外正式打卡，周期内记录保留 |
| 创建权重 | 只修正最后一个权重，可产生 2 和 -1 | 逐项校验正数且不超过 1；缺省项分配剩余份额；显式总和必须为 1，允许有限舍入误差；比例归一化后再次检查 |
| 状态日期冲突 | 保存进行中、查询变未开始；创建过去周期暂时显示进行中 | 日期状态统一推导；显式矛盾状态返回 400；过去周期创建时即为已过期 |
| 完成计划重启 | 新增步骤或撤销记录会恢复进行中 | 已完成计划冻结步骤、周期、目标天数和进度；状态回退、历史补分析与记录撤销均拒绝；名称、分类仍可修正 |

## 终态与日期规则

- 未开始和进行中由当前上海日期与计划周期决定。修改活动计划周期但不显式指定状态时，后端自动返回新周期对应状态。
- 显式提交未开始、进行中、已过期时，必须与新周期一致。不能用手动设置已过期来提前结束一个仍在周期内的计划。
- 已完成和已取消不可回退，不能更改周期、目标天数或步骤。仍允许修改名称、分类以及删除整个计划。
- 保留原有已过期终态约定：不能通过延长周期重新开始，需新建计划；仍可对原有效周期内已保存的待分析记录进行补分析，但不会把已过期计划改为已完成或进行中。
- 未开始计划可以安排步骤，但不能手动完成步骤。手动完成仅允许有效周期内的进行中计划。
- 已完成计划不允许撤销旧学习记录或补分析。这个约定刻意取代旧文档中的“完成后撤销会重新打开计划”。

## 周期修改确认协议

前端每次保存周期变化时重新请求正式打卡历史，计算早于新开始日期或晚于新结束日期的记录。边界日期包含在周期内。存在受影响记录时显示：

> 未在新计划周期内的打卡记录将清零，是否确认修改？共 N 条，删除后无法恢复。学习记录和学习进度保留。

“暂不修改”关闭确认提示但保留编辑表单，不发送更新请求。历史请求失败时不提交。查询与确认期间阻止重复保存；提交使用生成提示时的表单快照。

确认后通过原有 `PUT /api/v1/tasks/{taskId}` 发送两个附加字段：

```json
{
  "startDate": "2026-10-25",
  "discardOutsideCheckIns": true,
  "confirmedDiscardCheckInIds": [21]
}
```

后端先锁定计划行、校验归属、周期及状态，再重新读取受影响记录。只有明确确认且受影响记录 ID 集合完全一致才允许删除；缺少授权、伪造 ID 或确认期间新增了受影响记录时返回业务码 409，要求重新预览确认。前端不会自动重试破坏性操作。

周期修改与正式打卡删除属于同一事务，任一步失败共同回滚；正式打卡创建和学习记录写入原本也使用相同计划锁，避免确认检查与打卡写入交错。清理对象仅为正式打卡记录，学习行为日志、待分析记录和学习进度保留；原日期已在新周期外的待分析记录不能补分析。此处清零不代表抹除全部学习经历，也不承诺将来再次扩大周期后仍禁止原有效记录补分析。

打卡数、连续天数、完成率和最近七天趋势本来就来自真实记录，删除后重新查询即可反映新结果，无须保存额外统计副本。实际验证：两条打卡中清理昨天的一条，保留今天的一条；目标 5 天时已打卡 1 天、当前连续 1 天、完成率 20%，看板同步更新。

## 权重处理

所有输入在创建主计划之前完成校验。每个计划包含 1 至 100 个非空步骤，内容不超过 255 字；填写权重必须满足 `0 < weight <= 1`。未填写项平均分配剩余份额，不能出现剩余份额为零或负数。

全部显式填写时，权重总和应为 1。只允许每项四位小数量级的舍入差，不把任意错误总和当作舍入问题。用 BigDecimal 按比例归一化，向下保留四位小数，最后一项只吸收舍入余量，并重新验证每项有效性。极小权重归一化后变成零时拒绝保存。手动创建与旧 AI 自动创建接口复用同一套校验。

示例：`[2, 0]`、`[-1, 2]`、`[0.2, 0.2]` 均拒绝；`[0.6, null, null]` 得到 `[0.6, 0.2, 0.2]`；`[0.3333, 0.3333, 0.3333]` 归一化后精确合计 1。
