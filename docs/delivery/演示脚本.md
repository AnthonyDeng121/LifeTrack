## 一 录制前准备

1. 按[使用说明](提交清单与使用说明.md)启动 MySQL、后端、前端；需要演示真实 AI 时另配密钥并启用 AI 服务。
2. 打开浏览器、根目录 README、开发设计文档、AI 辅助开发记录、证据索引和终端。关闭无关页面，不展示 `.env`、数据库密码、Token 或模型密钥。
3. 选一个专用本地演示手机号，点击“查看演示验证码”登录。当前没有真实短信发送；不同号码的数据相互隔离。一键登录复用 dev_admin，若其已有数据，不要清空，也不要宣称看板应从零开始。
4. 以上海业务日期为 T。创建计划 A，开始 T、结束 T+6 天、目标 5 天、一个权重 100% 的步骤；标题可用“课程验收计划 A”。计划 B 用于取消演示，参数相同。
5. 如果新机器或环境有变，先运行 `./verify-course.ps1`。确定性验收不需要模型密钥，但需要 Python 测试依赖；模型演示另行预演一次。

## 二 正常业务闭环

建议录制约 6 至 8 分钟讲清这一部分。

| 顺序 | 操作 | 观察与讲解 |
| --- | --- | --- |
| 1 | 展示标题、课程选题和入口 | “本项目基于已有 LifeTrack 改造，先完成学习计划和打卡闭环，AI 是增强能力。” |
| 2 | 登录专用账号 | 解释 dev 是后端环境，不是某个用户角色；本地验证码不等于真实短信认证 |
| 3 | 创建 A，进入详情 | 标题、分类、起止日期、5 天目标和一个步骤真实保存 |
| 4 | 编辑 A 的标题，保存并刷新 | 展示修改后的标题与周期仍存在，说明数据由后端与 MySQL 保存 |
| 5 | 记录页选择 A，直接点击今日打卡 | 无备注与时长输入；显示今日已打卡，刷新并重新选择后状态保留；按钮禁用 |
| 6 | 查看 A 的打卡历史和概览 | 新账号首次打卡应为 1 天、当前连续 1、最长连续 1、目标达成率 20%；学习进度仍为 0、时长为 0 |
| 7 | 在详情完成唯一子步骤 | 学习进度100%、打卡率20%，仍进行中，可继续打卡和填写学习情况；双达标才完成 |
| 8 | 创建 B 并今日打卡 | 同一天两个计划不增加两个全局自然日；展示计划完成率与打卡率是不同指标 |
| 9 | 编辑 B 状态为已取消 | B 历史仍可查询，但退出全局打卡、时长、趋势、进度和完成率统计 |
| 10 | 展示状态与日期筛选、历史分页 | 页面替换当前页，不无限追加；筛选打卡历史不会把完整概览误当作筛选统计 |

A仅学习达标时不进入首页已完成计划数。演示双达标可另建目标1天的计划，先打卡再完成步骤，观察自动完成及新增被拒。首页按全部未取消计划计算。只打卡不产生学习日志，不伪造历史。

## 三 至少四个异常场景

建议先现场点出前端限制，再用真实 HTTP 脚本展示后端也会拒绝。不要把“按钮禁用”作为后端唯一证据。

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 空计划 | 新建表单不填标题，点击保存 | 显示空标题提示，不新增计划 |
| 非法周期 | 结束早于开始，或目标天数大于周期天数 | 明确提示，后端拒绝非法数据 |
| 同日重复打卡 | 已打卡后看按钮，再运行重复 HTTP 用例 | 页面已完成状态；真实接口 409，数据库只有一条 |
| 周期外日期 | 运行验收脚本中的周期外请求 | HTTP/code 400，不增加打卡 |
| 未来日期 | 运行未来日期请求 | HTTP/code 400，不提前制造连续天数 |
| 终态修改 | 已完成 A 后尝试改步骤或继续打卡 | 操作禁用或后端拒绝，不能回退 |

在根目录运行以下已有脚本，可重复验证异常；它们各自建立并清理临时计划，不是继续修改视频里的 A、B：

```powershell
.\backend\scripts\verify-p1-acceptance.ps1
.\backend\scripts\verify-business-rules.ps1
```

未指定 Token 时脚本使用共享开发账号；可选 `-Token` 使用专用账号，但不要把 Token 展示在录屏或命令历史中。脚本输出的 `historyApiCheckIns` 是接口历史数量；直接 SQL 验证由隔离集成测试及已保存证据提供。

如需要展示数据库，可仅查询本次自己的计划 ID；不直接修改业务表造数据。删除演示放在最后，只删除本次创建的 A、B，先展示历史与统计，再确认关联数据清理后的结果。

## 四 AI 演示与降级

新增验收：两个指标任一不足都不能直接设COMPLETED；先学完可继续打卡和填复习记录，先打卡达标可继续打卡和学习；双达标后两类新增均拒绝。人工结束保留历史，不冒充完成。分页使用上一页/下一页；网络重发同次学习提交不重复累计。

首页情绪寄语已删除。模拟或实际遇到慢AI周反馈时，基础统计应先显示；确定性前端测试以挂起反馈Promise验证此规则，不把该带桩测试称为真实模型测试。

有可用模型时：填写“学习计算机网络”，选择 3 步，生成预览；填写“重点分析 DNS、HTTP、TCP 抓包，最后完成一次可验证的网页访问实验”等调整建议；确认合适后保存。说明预览与重新生成不提前创建计划，步骤最终验收不代表已经学会。

学习记录先选择所属计划，填写演示学习内容、1小时30分钟，观察分析成功后累计90分钟及首次自动打卡；时长不使用自然语言估算。普通进度估算上限与完成证据由后端校验。不要声称模型可以客观判断掌握程度，也不要承诺模型每次输出一致。

模型不可用时：展示 AI 创建的错误和切换手动模式，继续创建、打卡、查询统计。提交学习记录后原文自动保留，但不计入时长、不自动打卡；“重新分析”失败仍保留，成功才计入原记录填写的时长，重复重试不得再次累计。模型故障的确定性 HTTP/MySQL 用例已保存，不需要在录制时公开密钥或破坏本机配置。
