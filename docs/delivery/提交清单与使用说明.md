## 二 新电脑首次运行

### 准备环境与代码

安装 MySQL 服务和客户端、JDK、Node/npm。只运行核心业务可以不启用 AI；全套验收还需要 Python 及测试依赖。版本优先参照[已验证环境](../verification/README.md)，不同版本先复测。

获取仓库，进入项目根目录，安装前端依赖：

```powershell
cd frontend
npm ci
cd ..
Copy-Item .env.example .env
```

在本机 `.env` 填写 `DB_USERNAME`、`DB_PASSWORD`，并将 `JWT_SECRET` 换为足够长的随机值；数据库地址不同时修改 `DB_URL`。开发与演示均填写 `SPRING_PROFILES_ACTIVE=dev`。不要把配置值贴到提交材料或在视频中展示。

### 初始化日常数据库

MySQL 服务器需要先安装并启动；项目 SQL 创建数据库和表，不安装服务器。使用 MySQL Workbench 打开并执行 `backend/sql/init_db.sql`，或者在 MySQL 客户端执行 `SOURCE 你的实际绝对路径/backend/sql/init_db.sql;`。路径含空格或中文时，优先使用图形客户端打开脚本，避免终端路径解析问题。

默认数据库名是 lifetrack；SQL 中数据库名与 DB_URL 要一致。首次建库后在根目录执行：

```powershell
$env:FLYWAY_ADOPT_BASELINE = "true"
.\start-local.ps1
Remove-Item Env:FLYWAY_ADOPT_BASELINE
```

脚本成功后再移除一次性开关，不将其长期写入 `.env`。若启动失败，先检查日志，不能因为删掉开关就认为初始化完成。基线 1 表示当前总脚本结构已建立，后续 V2 及之后的迁移由启动过程执行；已接管数据库不重放总脚本。

打开 `http://localhost:5173/`，后端为 8081，接口描述为 `http://localhost:8081/v3/api-docs`。首次没有预置个人计划是正常情况，登录后创建自己的数据。

### 可选 AI 服务

需要真实 AI 时在 `.env` 填写本机模型密钥和模型参数，然后先停止基础服务，再启三端：

```powershell
.\stop-local.ps1
.\start-local.ps1 -WithAI
```

启动脚本创建 AI 虚拟环境并按 requirements.txt 安装依赖。真实模型不可用不影响计划和打卡基本规则，但可能影响可选功能的反馈和耗时。

### 全套自动化验收

没有模型密钥也能运行确定性测试。若尚未通过三端启动创建 Python 虚拟环境，先在根目录手动准备：

```powershell
python -m venv AI_Server/venv
.\AI_Server\venv\Scripts\python.exe -m pip install -r AI_Server/requirements.txt
.\verify-course.ps1
```

验收需要数据库账号有创建、使用和清理临时测试库的权限。脚本生成 lifetrack_test_*，与日常库隔离，结束后默认清理；日常重新启动项目仍连接 DB_URL，不会换一套数据。原始日志在本机 `.verification/`，公开结果在 `docs/verification/`。

### 日常停止与再次启动

```powershell
.\stop-local.ps1
.\start-local.ps1
# 需要 AI 时使用 .\start-local.ps1 -WithAI
```

日常无需再次设置 FLYWAY_ADOPT_BASELINE，也不再执行初始化总脚本。先停止现有服务再重启，避免端口占用。更新代码后若含新 Flyway 迁移，按迁移设计备份并升级。
