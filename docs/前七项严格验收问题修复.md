## 实现取舍

不新增数据库字段或修改Flyway基线。步骤编辑复用父计划的乐观锁版本，计划行锁串行执行写入，事务把进度重置、日志解除关联与版本更新一起提交，非法权重或版本冲突必须整体回滚。用户明确选择KEEP是对文字修正的确认，不声称系统能自动证明两个目标含义相同。

客户端本地缓存只保存结果尚未确认的提交，服务器唯一约束仍是防重复计时的最终保障。服务端已应用后重发返回replayed，不再次分析或计时。恢复依赖原浏览器本地存储仍存在；主动清除站点数据不属于可恢复保证。不把平台带桩存储测试称作真实浏览器刷新验收。

## 课程报告可用内容

1. 用反例说明数据库行锁与版本控制解决不同问题：锁控制写入顺序，版本识别过期表单。
2. 解释“学习内容”与“学习成果”之间的关系，目标实质改变不能默认继承旧成果；历史保留和当前进度重置可以同时满足。
3. 幂等性需要客户端生命周期与数据库唯一约束共同保证，只有后端唯一键并不能解决刷新后换ID的问题。
4. 日期状态是业务规则，应在操作入口校验，定时任务只是补充；外部参数应在落库前给出明确400。
5. 按真实HTTP/MySQL、平台带桩和真实浏览器区分验证证据，避免把测试数量当作业务正确性证明。
