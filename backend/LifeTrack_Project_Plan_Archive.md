# 「LifeTrack AI」项目概览

## 核心痛点
针对大学生群体中普遍存在的“做了很多，但感觉什么都没做”的焦虑感，解决传统 ToDo List 缺乏反馈、难以量化努力程度的问题。

## 项目目标
- **可视化进度**：将模糊的日常行为转化为结构化的成长轨迹。
- **正向反馈**：通过 AI 分析将焦虑情绪转化为成就感。

## 核心功能 (精华版)
1. **AI 任务拆解**：输入目标（如“学会 Spring Boot”），AI 自动生成带权重的子任务。
2. **AI 进度判断 (核心创新)**：支持自然语言输入（如“写了登录功能”），AI 自动匹配任务并计算贡献度百分比。
3. **全维度记录**：涵盖学习与非计划行为（如娱乐、休息），构建完整的用户画像。
4. **情绪激励系统**：基于真实行为生成非“鸡汤”式的个性化建议与反馈。

## 技术路线
- **后端**：Java (Spring Boot)
- **AI 能力**：大模型 API 调用 + Prompt 工程
- **前端**：移动端 App / 小程序

## 第二轮回复

### **🚀 LifeTrack AI 技术实现方案**

既然你负责后端与 AI 核心，并且有 **Spring Boot** 背景，我将直接按照生产级标准为你设计方案。

---

### **1️⃣ 数据库设计 (Database Schema)**

我们需要支持“任务树”结构和“行为流”记录。建议使用 MySQL 8.0。

#### **核心表结构：**

| 表名 | 说明 | 核心字段 |
| :--- | :--- | :--- |
| **`users`** | 用户基础表 | `id`, `username`, `password`, `avatar`, `created_at` |
| **`tasks`** | 主任务表 (Goal) | `id`, `user_id`, `title` (目标), `status` (进行中/已完成), `total_progress` (0-100), `ai_analysis` (AI 生成的建议) |
| **`sub_tasks`** | 子任务表 (Steps) | `id`, `task_id`, `content` (步骤内容), `weight` (权重, 如 0.2), `is_completed`, `order_num` |
| **`action_logs`** | 行为日志表 (Records) | `id`, `user_id`, `raw_input` (原始自然语言), `task_id` (匹配到的任务), `contribution` (AI 判定的进度增量), `created_at` |
| **`user_profiles`** | 用户画像表 | `id`, `user_id`, `interest_tags` (JSON 格式), `energy_level`, `updated_at` |

---

### **2️⃣ 后端架构设计 (Spring Boot)**

我们将采用经典的 **Controller-Service-Manager-Mapper** 四层分层体系，其中 **Manager** 层专门用于处理 AI 接口的异步调用和复杂业务编排。

#### **核心 Controller 定义：**

```java
@RestController
@RequestMapping("/api/v1")
public class LifeTrackController {

    // 1. 任务拆解：用户输入目标，返回 AI 拆解后的建议
    @PostMapping("/tasks/deconstruct")
    public Result<List<SubTaskDTO>> deconstructTask(@RequestBody String goal);

    // 2. 进度同步：用户输入自然语言，AI 更新进度
    @PostMapping("/actions/sync")
    public Result<ProgressUpdateDTO> syncAction(@RequestBody ActionRequest request);

    // 3. 情绪反馈：获取今日 AI 寄语
    @GetMapping("/feedback/daily-motivation")
    public Result<String> getDailyMotivation(@RequestParam Long userId);
}
```

#### **AI 调用服务设计 (`AIService`):**
利用 Spring Boot 的 `@Service` 注解对 AI API 进行封装。建议使用 **RestTemplate** 或 **WebClient** 调用外部大模型（如 DeepSeek 或 OpenAI）。

---

### **3️⃣ AI 核心逻辑与 Prompt 模板 (AI Core)**

这是项目的“灵魂”。李想和魏欣岳需要设计以下两套关键 Prompt。

#### **A. 任务拆解 Prompt (Goal Deconstructor)**
*   **输入：** “我这学期想学会 Spring Boot”
*   **Prompt：** 
    > “你是一个专业的学业导师。请将用户输入的目标拆解为 5-8 个可量化的具体子任务，并为每个任务分配一个权重（总和为 1.0）。请严格以 JSON 格式返回，格式如下：`[{ "step": "...", "weight": 0.2 }]`。”

#### **B. 进度判断 Prompt (Progress Analyzer) ⭐**
*   **输入：** 
    *   当前目标：“学会 Spring Boot”
    *   子任务列表：“[1. 基础语法, 2. Web 开发...]”
    *   用户行为：“我今天写了一个 RestController 接口”
*   **Prompt：**
    > “你是一个进度分析助手。基于当前任务列表，分析用户的行为对哪个子任务有贡献，并给出该行为在整个主任务中的进度增量百分比（0.01 - 0.1）。如果行为不属于任何任务，请标记为‘生活琐事’。”

---

### **4️⃣ 整体业务流程 (Workflow)**

1.  **用户发布目标**：前端发送 `goal` -> 后端调用 AI 拆解 -> 返回子任务列表 -> 用户确认保存。
2.  **用户日常输入**：用户输入“看了 2 节 Spring Boot 网课” -> 后端调用 AI -> AI 返回：*“属于子任务 2，进度增加 5%”*。
3.  **数据更新**：后端更新 `sub_tasks` 状态，并累加 `tasks` 表的 `total_progress`。
4.  **激励反馈**：用户打开 App -> 后端读取今日 `action_logs` -> AI 生成一段暖心的总结（如：“你离 Spring Boot 大师又近了一步，快去休息吧”）。

---

### **🛠️ 技术栈清单 (Tech Stack)**

*   **后端：** Spring Boot 3.x, MyBatis Plus (比 MyBatis 更快), MySQL 8, Redis (缓存 AI 响应)。
*   **AI：** 通用大模型 API (建议首选 DeepSeek-V3，性价比极高)。
*   **前端交互：** Axios + JSON 序列化。
